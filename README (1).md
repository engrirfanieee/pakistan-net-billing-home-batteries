# Pakistan Net Billing and Home Battery Storage: Code and Data (2026–2035)

**Supporting code, processed data and simulation results** for the research manuscript:

> **Home batteries under net billing: load defection, fixed-cost recovery and time-differentiated export credits in Pakistan**  
> Muhammad Irfan Habib  
> Department of Electrical Engineering Technology, National Skills University Islamabad, Pakistan

## Overview

This repository supports a study of how Pakistan's 2026 transition from net metering to net billing affects residential solar photovoltaic (PV) and behind-the-meter battery investment, electricity purchases, grid defection, and electricity distribution companies' fixed-cost recovery.

The analysis combines:

- Hourly demand profiles for **34 residential consumers in Lahore**, processed from the Pakistan Residential Electricity Consumption (PRECON) dataset.
- Hourly solar PV generation estimates based on **PVGIS typical meteorological year** data for Lahore.
- A joint **capacity-and-dispatch linear programme** to optimise household PV and battery capacity and hourly energy flows.
- Comparisons of grid-only supply, legacy net metering, net billing, time-differentiated net billing, and off-grid operation.
- An annual **stock-and-flow model for 2026–2035** linking prosumer adoption, electricity tariffs and utility fixed-cost recovery.

The supplied results include **1,530 household optimisation cases** and **2,448 response-surface cases**, along with system simulations, manuscript tables and derived numerical summaries.

## Software requirements

Use Python 3 with `numpy`, `pandas`, `scipy` (HiGHS linear programming solver), `pvlib`, and `matplotlib`. The original repository notes **pvlib 0.16.1**. Rebuilding the raw PRECON data also requires a Parquet engine such as `pyarrow`.

```bash
python -m pip install numpy pandas scipy matplotlib pvlib==0.16.1 pyarrow
```

Other package versions were not pinned in the supplied archive. Exact numerical reproduction can depend on the solver and library versions.

## Reproduce the analysis

### A. Use the supplied processed data

The provided `data/load_profiles_calendar.csv` and `data/pv_profile_lahore.csv` allow the optimisation to run without downloading the original demand and weather files.

From the repository root, run:

```bash
python code/run_household.py
python code/run_grid.py
python code/system_model.py
python code/analysis_system.py
python code/make_numbers.py
python code/fig_framework.py
```

These scripts generate or update the household results, response-surface results, annual system results, system table, manuscript statistics and figures. **The optimisations are computationally substantial** and will overwrite existing output files.

For the household figures and sample-characteristics table, first obtain `data/precon_metadata.csv` from the PRECON dataset. Then run:

```bash
python code/analysis_household.py
```

`analysis_household.py` also needs `results/net_import_base.npz`, which is created by `run_household.py` and is absent from the supplied ZIP. You can inspect the existing CSV and JSON results without rerunning the optimisations.

### B. Rebuild the processed input profiles from raw data (optional)

1. Obtain the original PRECON data and place the household files in `data/precon_raw/` with names matching `House*.csv`. Each CSV must contain `Date_Time` and `Usage_kW` columns.
2. Obtain the PVGIS TMY CSV for **31.520° N, 74.360° E (Lahore)** and save it as `data/pvgis_tmy_lahore.csv`. The parser in `pv_model.py` expects the PVGIS CSV layout used by the project, including its header lines and meteorological column names.
3. Run:

```bash
python code/precon_process.py
python code/load_profiles.py
python code/pv_model.py
```

The PRECON measurement period is **1 June 2018–31 May 2019**. The processing retains households with no more than 1% missing hours and no more than 5% zero-consumption hours. The hourly demand and PV profiles use **2023 as a common, non-leap calendar index for aligning month, day and hour**; this is not the original measurement year of the demand observations.

## Scenario definitions

| Label | Description |
| --- | --- |
| `GRID` | Grid supply only |
| `NM` | Legacy net metering |
| `NB_noBESS` | Net billing with PV but no battery |
| `NB` | Net billing with optimised PV and battery |
| `TNB` | Time-differentiated net billing; evening credit sensitivity |
| `OFF` | PV and battery without a grid connection |
| `TNB35` / `TNB46` | System-model scenarios with PKR 35/kWh and RLNG-cost evening export credits |

Model parameters, including the retail time-of-use tariffs, net-billing export credit, PV and battery investment costs, battery constraints and discount rate, are specified in `code/params.py`. The study uses perfect-foresight hourly dispatch; its dispatch outcomes represent economic potential rather than the performance of a real-time controller.
